# 備品・機材の貸出返却台帳

## 概要

うみねこデザイン室（架空）の共用備品を、QRコードで手軽に貸出・返却できるブラウザアプリです。返却遅れと「誰が何を借りているか」を見える化します。デモ用の架空データです。

## 主な機能

### 1. 備品・メンバーの管理

- 備品の管理番号、名前、カテゴリ、保管場所、登録日、登録者、備考を追加・編集・削除。
- 備品詳細で管理番号を内容としたSVGのQRコードを表示し、1枚ずつ印刷。
- メンバーの名前・所属・有効／休止を管理。休止中のメンバーには新規貸出できません。
- 貸出中の備品、その備品を借りているメンバーは削除できません。削除後も過去の履歴内の名前・管理番号は保持します。

### 2. 貸出・返却記録

- カメラでQRを読み取り、貸出可能なら貸出画面、貸出中なら返却画面へ移動。
- カメラは背面を優先し、画面から離れると停止。映像は端末内だけで処理します。
- 権限拒否・カメラ非搭載・非HTTPSでは、管理番号の手入力や備品選択を利用できます。
- 貸出先、返却予定日、用途メモを記録。予定日の初期値は日本時間の今日から7日後です。
- 返却時は受取担当者と状態メモを記録。二重貸出・二重返却を防止します。

### 3. 返却遅れと現在の貸出状況の可視化

- ホームに返却遅れ件数を表示し、予定日・遅延日数の一覧へ移動。
- メンバー別に現在の貸出をまとめ、件数の多い順に表示。
- 履歴を貸出日の期間・備品・メンバーで絞り込み。
- 貸出回数、平均貸出日数、遅延返却率、よく借りられる備品トップ5を集計。
- 平均貸出日数と遅延返却率は、絞り込んだ履歴のうち返却済みの記録で算出。貸出日数は日本時間の日付差です。
- 履歴・貸出中一覧をBOM付きUTF-8 CSVで出力。日付入りのファイル名、引用符・改行の処理、数式注入対策に対応。
- JSONバックアップを書き出し、内容確認後に復元。

## 日時の扱い

日付は日本時間の `YYYY-MM-DD`、時刻は `HH:MM`、記録日時はその組み合わせで保存します。マウント後に現在時刻とlocalStorageを読み込みます。

初回と既定データへのリセット時に、開いた日の日本時間から相対的に架空の履歴を生成します。登録日は約1〜3年前、履歴は過去約11か月の範囲です。シードの記録は前日以前、9〜18時台に分散し、午前0時台でも未来の記録を作りません。

初期の貸出中は5件、返却遅れは9日と2日の2件、返却予定日が当日の備品は1件です。当日は遅延に含めません。生成後の記録日付は固定され、日が進むと遅延日数も増えます。画面の判定日は30秒ごとに更新します。

## 画面一覧

| URL             | 画面                                         |
| --------------- | -------------------------------------------- |
| `/`             | ホーム・備品カード・返却遅れ件数             |
| `/scan`         | QRカメラ読取・管理番号入力・備品選択         |
| `/items`        | 備品一覧・追加・貸出中CSV                    |
| `/items/[id]`   | 備品詳細・編集・削除・QR表示と単票印刷・履歴 |
| `/members`      | メンバー一覧・追加                           |
| `/members/[id]` | メンバー詳細・編集・削除・履歴               |
| `/lend/[id]`    | 貸出記録                                     |
| `/return/[id]`  | 返却記録                                     |
| `/lending`      | 貸出中・返却遅れ・メンバー別一覧             |
| `/history`      | 履歴・期間集計・CSV                          |
| `/backup`       | JSON書き出し・読み込み                       |
| `/about`        | デモの説明・既定データへのリセット           |

動的ルートは既定IDと共通シェル `local` を事前生成し、データ自体はクライアントで読み込みます。追加したレコードは `/items/local?record=ID` などのURLを使うため、ビルド後に追加したデータも静的配信で表示できます。通常の起動は `next start` です。静的出力を利用する場合は `next.config.ts` の `turbopack.root` を維持したまま `output: "export"` を追加し、生成した `out` を配信してください。

## データの保存先

ブラウザのlocalStorage、キー `ell:v1` を使用します。認証・DB・外部APIはありません。保存データの型、日付、参照、貸出期間の重複などを検証し、破損している場合は既定データに戻して通知します。

ブラウザ・端末間の自動同期はありません。同一ブラウザの別タブの更新は反映しますが、複数タブで同時に確定する操作をDBのように排他制御するものではありません。ブラウザの保存領域を削除する前にJSONバックアップをご利用ください。復元は検証と件数確認の後、台帳全体を置き換えます。

Service Workerは本番のみ登録します。台帳やページ応答のキャッシュは行わないシンプルな構成で、完全なオフライン動作は対象外です。

## 技術スタック

- Next.js 16 / App Router / TypeScript / React 19
- Tailwind CSS 4を含むcreate-next-app構成、画面スタイルはセクション別CSS
- qrcode（SVG生成）、jsqr（カメラフレーム読取）
- localStorage / MediaDevices / Service Worker / Web App Manifest
- ESLint / Prettier 3（printWidth: 100）
- Node.js標準テストランナーとTypeScript型ストリップ（Node.js 24で検証）
- 外部Webフォントなし。日本語のシステムフォントを使用

純粋関数は `src/lib/`、画面と部品は `src/components/`、ルートは `src/app/` に分離しています。

## ローカル起動方法

Node.js 24以降を使用し、このフォルダ直下で実行します。

```bash
npm install
npm run dev
```

http://localhost:3000 を開きます。カメラを利用する場合はlocalhostまたはHTTPS接続が必要です。

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

整形コマンド：

```bash
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

テストでは複数時刻のシード、遅延日数、QRの往復とSVG、二重貸出防止、返却、管理ルール、集計、CSV、バックアップ検証、シードのばらつきを確認します。

## デモデータについて

チーム「うみねこデザイン室（架空）」、メンバー7名（1名休止）、備品15点、貸出返却記録78件を用意します。すべて架空で、実在の企業・個人とは無関係です。

日付は開いた日からの相対で生成します。カメラは頻繁、ドローンは月1回程度など、備品・人によって利用頻度に偏りを設けています。貸出期間は1〜14日で、案件・用途は疑似乱数で選び、同じ月の案件に偏りを持たせています。返却済み履歴は2〜3日前まで続き、受取担当は借りた本人以外の有効メンバー、登録者は3名に分散します。状態メモは78件中22件に重複なく付き、一部には返却が遅れた理由を記録しています。「既定データに戻す」で、その時点の日付に合わせて再生成できます。
